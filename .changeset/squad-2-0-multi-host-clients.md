Squad 2.0: decoupled backend and multi-host client adapters. Add `squad init --client` and `squad upgrade --client` (copilot, claude, kiro, opencode, cursor, codex, antigravity) with additive, non-clobbering config merges, persisted in `.squad/config.json` `clients[]`; add the `HostProjection` / spec `ClientAdapter` SDK surface with canonical capability tokens under `@bradygaster/squad-sdk/client` (and the deprecated `/clients` alias), a host-agnostic coordinator prompt with per-host dispatch, locked/transactional repair and `team.md` backfill for handwritten `.squad/casting/registry.json` files during `squad upgrade` (including `--dry-run`), and the experimental `@bradygaster/squad-sdk/backend` conversation & harness contract (`LocalSquadBackend`, `DurableHttpSquadBackend`, `DefaultHarnessRegistry`, `createStateBackendStore`, and `squad_backend_*` MCP tools in `squad state-mcp`, enabled only by `--experimental-backend` or `SQUAD_EXPERIMENTAL_BACKEND=1`).

Casting repair details: the repair is per-record (valid records and their extra fields are preserved verbatim, the registry revision is bumped), archives the pre-repair originals under `.squad/casting/handwritten-archive-<sha256>/` by default, fails closed with a per-entry `dropped` list instead of silently discarding entries, derives backfilled agent ids from the `team.md` Charter column / `.squad/agents/*/charter.md` folders rather than from display names, reconciles a single Init Mode `history.json` snapshot, and never rolls a durable commit back.

Projection details: the Codex coordinator is emitted as a TOML custom agent (`.codex/agents/squad.toml` with `name`, `description`, `developer_instructions`); `.gitignore` entries are plain lines under a `# squad:<id>` comment (uninstall removes only those); merged files keep their existing line endings, JSON indentation and trailing-newline convention and are written atomically; OpenCode targets `opencode.jsonc` when it is the only config and refuses to clobber a JSONC file that contains comments; symlinked/junctioned ancestors of the repo root are accepted while symlinks escaping the root are still refused; a newly requested client whose host config could not be merged is reported but not persisted; `squad upgrade --dry-run --client <list>` previews the clients it would project.

Backend details: `SQUAD_BACKEND_URL` alone no longer enables the tools; the remote `durable-http` backend requires an `https://` base URL (plain `http://` only for localhost), never follows redirects, and times out health probes. The MCP bridge bundles no execution harness: `squad_backend_send_message` returns `unavailable` and `health`/`negotiate` report `executionAvailable: false` until a harness is registered. `.squad/backend/` is now git-ignored by `squad upgrade`. When a non-local state backend (git-notes, orphan) is configured, `createStateBackendStore` keeps its lock files in a deterministic machine-local directory derived from the backend identity (`lockAnchor` / repo root) so `.squad/backend/` is never materialized in the team directory; and when a handwritten registry cannot be repaired, `squad upgrade` fails closed with the reason, the dropped entries and the fix instead of the generic pair-initialization error.
