Squad 2.0 pre-preview follow-up: runtime upstream inheritance, removal of personal squads, and state-bridge fixes.

- **Upstream inheritance works at runtime (F1).** `squad upstream add|sync` already wrote `.squad/upstream.json`; sessions now actually inherit from it. New runtime tool `squad_state_upstreams` (exposed over `squad state-mcp` to all 7 hosts) resolves every declared upstream from its locally materialized snapshot (`local` path, `.squad/_upstream_repos/<name>/` for `git`, export file) and returns inherited skills, decisions, routing, wisdom and casting policy with `upstream:<name>@<ref>` provenance. Resolution is deterministic (local `.squad/` wins, then declared order, depth-first through each upstream's own `upstream.json`, default depth limit 3), de-duplicates diamonds, detects cycles, reports `missing` / `invalid` / `unavailable` / `stale` sources with an actionable diagnostic, and **never fetches at session start** (`squad upstream sync` is the only network step). The canonical coordinator gains an `Upstream Inheritance` section (digest item 16a on every host), and `squad doctor` / `squad status` show the same resolution. SDK: `ResolvedUpstream` gained `provenance`, `origin`, `ref`, `depth`, `via`, `status`, `diagnostic`, `squadDir`, `lastSynced`; `UpstreamResolution` gained `diagnostics` and `maxDepth`; new `buildEffectiveUpstreamContext`, `formatUpstreamReport`, `upstreamProvenance`, `DEFAULT_UPSTREAM_MAX_DEPTH`, `DEFAULT_UPSTREAM_STALE_DAYS`; `resolveUpstreams(squadDir, storage?, options?)` accepts a source that already is a `.squad/` directory.
- **BREAKING: personal squads are removed (F9).** `squad personal`, `squad consult`, `squad extract`, ambient `~/.config/squad/personal-squad` agent discovery, Ghost Protocol spawn rules, consult-mode routing, and the `SQUAD_NO_PERSONAL` / `SQUAD_PERSONAL_DIR` switches are gone. `squad init` no longer sets `config.json` `teamRoot` to the global squad root and never writes outside the project `.squad/`. SDK removals: `resolvePersonalSquadDir`, `ensurePersonalSquadDir`, `ensureSquadPathTriple`, `isConsultMode`, `ResolvedSquadPaths.personalDir`, `SquadDirConfig.consult` / `extractionDisabled`, `InitOptions.extractionDisabled`, the `@bradygaster/squad-sdk/agents/personal` subpath (`resolvePersonalAgents`, `mergeSessionCast`) and the `sharing/consult` module (`setupConsultMode`, `extractLearnings`, `mergeToPersonalSquad`, `PersonalSquadNotFoundError`, …). Added read-only `legacyPersonalSquadPath()` / `detectLegacyPersonalSquad()`. **Nothing is deleted, moved or rewritten:** `squad upgrade` and `squad doctor` print a one-time notice when a 1.x personal squad directory or a `teamRoot` pointing at the global root is detected, and the dead subcommands print the same notice and exit non-zero. Migrate explicitly with `squad export` (in the old directory) and `squad import` (in the project). `squad init --global` / `squad upgrade --global` still manage the *global* squad but no longer bootstrap `personal-squad/`.
- **State bridge fixes.** `squad_state_health` reports `State backend: local|orphan|two-layer` (plus storage class and team squad dir) as the coordinator digest promised (F6); `squad_state_list` without `dir` lists the root on git-backed backends instead of failing (F8); Claude Code declares `background-runs` in `capability-matrix.json` and `CAPABILITY_TOKENS_BY_HOST` (F7). `ToolRegistry` accepts `{ backendName }` as a trailing options argument.
- **Docs.** `features/upstream-inheritance.md` now describes exactly what ships (earlier entries win conflicts, no implicit fetch, statuses, SDK API); headless Claude Code needs `claude --mcp-config .mcp.json` (F5); Azure DevOps support is detection + `squad triage|watch` via `az`, interactive Issues mode is GitHub-only (F3); GitLab issue tracking is planned, not shipped (F2); upgrading guide gains "Personal squads removed".
