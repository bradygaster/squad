Central model resolver (#1720): `resolveAgentModel` (an alias of `resolveModel`) from `@bradygaster/squad-sdk/agents` adds `config`, `session` and `fallback` sources, applies the exported `MODEL_RESOLUTION_PRECEDENCE` (user-override > config > session > charter > task-auto > default), and returns a `rationale` for every choice (typed as `ModelResolution`; `ResolvedModel.rationale` stays optional so consumer-built values remain valid). `auto` (any case) means "no preference" at every layer, including a per-spawn override. A session-picked model is inherited by every sub-agent spawn with source `session`. When a model listed in `unavailableModels` is in its tier chain, fallback moves only forward to the next available entry; models outside the chain search it from the head; with no candidate left, `omitModel` is set. The returned `fallbackChain` lists only available entries, starting at the selected model when it is in its chain, so retries never move back toward the head. `ModelFallbackExecutor.execute` accepts an optional `{ platformDefault }` callback that runs model-less when the resolution has `omitModel`; it never calls the model callback with an empty id.

The root `resolveModel` export (string-returning, reads `.squad/config.json`) is now a compatible adapter over the central resolver, so it no longer returns a literal `auto`. `AgentLifecycleManager.spawnAgent` now applies persistent `.squad/config.json` preferences (`agentModelOverrides`, `defaultModel`, `economyMode`) and records provenance on `AgentHandle.modelResolution`, OTel span attributes and an `agent:milestone` `model.resolved` event. New helpers: `isModelPreference`, `persistentConfigModel`. Coordinator spawn guidance and `model-selection-reference.md` no longer hard-code model IDs; spawn acknowledgments show model, source and rationale, with catalog IDs kept in a separate appendix. `AgentLifecycleManager.spawnAgent` accepts `sessionModel` and `unavailableModels`; an exhausted chain omits `model` from the session config. Under a cost policy, an explicit over-ceiling pick keeps the forward-only fallback cursor. Availability fallback also honors the active cost ceiling (`config.costPolicy` or `sessionCostPolicy`): catalog-known candidates above it are skipped, so an unavailable out-of-catalog pick (for example `hydrafusion`) falls back only to an in-ceiling entry or omits `model`; an available explicit pick still passes through unchanged.
